# Безопасность LÜMEN

## Что защищено и как

| Угроза | Защита |
| :--- | :--- |
| Перехват трафика | HTTPS (TLS) на Railway; заголовок HSTS — браузер ходит только по HTTPS |
| Утечка данных из хранилища | Отчёты шифруются **AES-256-GCM** (аутентифицированное шифрование) перед записью на диск и в Supabase. Ключ — `LUMEN_ENCRYPTION_KEY`, только в переменных сервера |
| Доступ к базе напрямую | Supabase: RLS включён, у ролей `anon`/`authenticated` прав нет; backend ходит сервисным ключом, который не попадает в браузер |
| Утечка ключей | Ключи только в `.env`/переменных Railway; маскируются в ошибках; не попадают в отчёты, логи (httpx-логи URL отключены — в URL Telegram есть токен), frontend и Git |
| Доступ администратора | Вход по паролю `LUMEN_ADMIN_PASSWORD` → подписанная HMAC-SHA256 сессия в cookie `HttpOnly; Secure; SameSite=Strict` на 12 ч (JavaScript её не читает — XSS не украдёт); защита от подбора: 5 попыток за 15 мин с IP; сравнение за постоянное время |
| Обход лимитов подменой IP | IP берётся из записи, которую добавил наш прокси (`X-Forwarded-For` справа, `LUMEN_TRUSTED_PROXY_HOPS`), а не из левой части, которую пишет клиент |
| Подбор пароля по украденной cookie | Сессия подписана отдельным серверным ключом (`LUMEN_SESSION_SECRET`), а не хешем пароля; смена пароля обнуляет все сессии |
| Чужие правки ответов на вопросы | Отвечать может только автор проверки (ключ редактирования выдаётся при загрузке и хранится в его браузере) или администратор |
| Огромные запросы | Тело больше 21 МБ отклоняется по `Content-Length` до чтения; SSE-поток живёт не дольше 30 мин; ID прогона проверяется по шаблону |
| CSRF | SameSite=Strict + для записей по cookie обязателен заголовок `X-Requested-With: lumen` |
| Расход квоты моделей | Публичный режим: проверка доступна всем с лимитами (20 анализов/час и 240 запросов/мин на IP, 10 анализов и 60 сообщений/час на чат бота); администратор без лимитов; `LUMEN_PUBLIC_AUDITS=0` закрывает проверку для гостей |
| Удаление и порча данных | Удаление только администратором; на публичном сервере без пароля администратора удаление запрещено |
| Конфиденциальность документов из бота | Прогоны из Telegram приватные: не видны в публичном списке, доступны только по ID (80 бит случайности) |
| Полностью закрытый сервер | `LUMEN_PRIVATE=1` — даже просмотр отчётов только с токеном (токен идёт в заголовке, не в URL) |
| Вредоносные файлы | Проверка по содержимому (сигнатуры), а не по расширению; отказ: исполняемые файлы, DOCX с макросами, zip-бомбы, PDF > 400 стр., огромные изображения, файлы > 20 МБ; загруженные файлы удаляются после анализа |
| XSS, кликджекинг | Строгий CSP (`script-src 'self'`, `frame-ancestors 'none'`), `X-Frame-Options: DENY`, `nosniff`; весь пользовательский текст в отчётах экранируется |
| Prompt injection в документе | Модель предупреждена, что документ — данные, а не инструкции; попытка внедрения фиксируется как дефект; все цитаты сверяются с документом; чат бота не раскрывает настройки |
| Path traversal | Имена файлов нормализуются, ID очищаются, статика отдаётся только из папки сборки |
| Запуск от root | Контейнер работает от непривилегированного пользователя `lumen` |

## Переменные безопасности

| Переменная | Значение |
| :--- | :--- |
| `LUMEN_ADMIN_PASSWORD` | пароль администратора (вход в панели; заголовок `X-API-Token` для скриптов) |
| `LUMEN_PUBLIC_AUDITS` | `1` (по умолчанию) — гости проверяют документы с лимитами; `0` — только администратор |
| `LUMEN_ENCRYPTION_KEY` | ключ шифрования: `python -c "import secrets,base64;print(base64.urlsafe_b64encode(secrets.token_bytes(32)).decode())"`. **Потеряете ключ — зашифрованные отчёты не прочитать.** Старые незашифрованные записи читаются и дальше |
| `LUMEN_SESSION_SECRET` | ключ подписи сессий и ключей редактирования (длинная случайная строка) |
| `LUMEN_TRUSTED_PROXY_HOPS` | число доверенных прокси перед сервером (Railway — `1`) |
| `LUMEN_PRIVATE` | `1` — закрыть и просмотр |
| `LUMEN_PUBLIC_DEMO` | `1` (по умолчанию) — демо без токена (смоделированные ответы, без затрат) |
| `LUMEN_RATE_AUDITS`, `LUMEN_RATE_REQUESTS`, `LUMEN_BOT_AUDITS`, `LUMEN_BOT_MESSAGES` | лимиты |
| `APP_ENV` | `production` (задано в Dockerfile) |

## Что ещё нужно для коммерческого запуска

* Учётные записи и роли (SSO банка), разделение данных по организациям вместо общего токена.
* Лимиты в Redis вместо памяти процесса (при нескольких экземплярах сервера).
* Ротация ключей шифрования, аудит-лог действий, резервное копирование Supabase.
* LLM-провайдер с договором о неиспользовании данных (бесплатный тариф Gemini может использовать запросы для
  улучшения моделей — не загружайте туда реальные банковские документы).
* Регулярный `pip-audit`/`npm audit` и пентест перед продом.
